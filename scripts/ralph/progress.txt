## Codebase Patterns

### Backend Patterns
- SQLAlchemy models use `Mapped[]` type annotations (SQLAlchemy 2.0 style)
- Models use `mapped_column()` with `server_default` for defaults
- Use `TYPE_CHECKING` for forward references in models
- Models inherit from `Base` (from `.base`)
- Models exported in `backend/src/models/__init__.py`
- API routes in `backend/src/api/routes/` and registered in `__init__.py`
- Pydantic schemas in `backend/src/api/schemas.py`
- Use `structlog` for logging, never `print()`
- Dependencies in `backend/src/api/dependencies.py`
- Services in `backend/src/services/` and exported in `__init__.py`
- Config uses `@lru_cache` decorated `get_settings()` function
- Alembic migrations follow pattern: `001_description.py`, `002_description.py`, etc.

### JWT/Auth Patterns
- Use PyJWKClient for JWKS-based JWT validation
- Cache JWKS client at module level for performance
- Supabase JWKS URL: `{SUPABASE_URL}/auth/v1/.well-known/jwks.json`
- Validate both audience ("authenticated") and issuer
- Use `HTTPBearer` security scheme for Authorization header
- Create separate dependencies: `get_current_user`, `get_optional_user`, `get_or_create_user`
